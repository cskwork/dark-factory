dark-factory에이전트가 돌리는 티켓 기반 소프트웨어 라인

싼 깨우미가 할 일이 있는지 판단하고, 비싼 오케스트레이터는 지시만 하며, 작업자가 일하고, 결정론적 스크립트가 "완료"를 판정합니다. 사람에게는 클릭 한 번짜리 결정 페이지로만 묻습니다.

cd dark-factory
python3 -m unittest discover -s tests -v

흐름·통과사람 대기정지·실패

더 큰 모델로는 안 풀리는 문제

에이전트는 보통 같은 일을 더 빠르게 하는 데 쓰입니다. 공장은 속도 대신 레버리지를 삽니다. 이 하네스를 만든 2일 파일럿에서 라인은 이런 이유로 멈췄습니다.

관찰 (2일 파일럿)의미하네스의 대응
예약 tick 26회 중 19회는 할 일이 없었는데도 매번 최상위 모델이 런북 전체를 읽음유휴 상태에 비용 지출비싼 모델이 뜨기 전에 가드 스크립트가 유휴를 판정
진행 중 기능 15건 중 7건이 증거 단계에서 사람을 기다림병목은 모델 품질이 아니라 환경과 데이터preflight 탐침이 필요한 사람 조치를 정확히 짚고 빠르게 실패
"완료" 주장을 그 일을 한 모델이 스스로 판정외부 검증자 부재완료에는 검증자 JSON(브랜치·배포·댓글 되읽기)이 필요
한 티켓의 커밋이 다른 티켓 브랜치에 있어 브랜치 이름 조회가 "브랜치 없음"이름 규칙은 깨진다ticket_refs가 커밋 제목 마커로 찾고 함께 승격된 키를 나열
머지 충돌이 라인을 멈춤사람이 반복 작업을 중계에이전트가 해소하고 다른 에이전트가 리뷰하며 스크립트가 시험. 의미 충돌은 여전히 사람에게

tick 한 번이 지나가는 길

판정은 가능한 한 싼 쪽에서, 상태 변경은 권한이 있는 쪽에서만 합니다. 각 레인은 자기 일만 합니다.

검증에 실패하면 완료되지 않고 오케스트레이터로 돌아가며, 실패는 lessons.jsonl에 쌓여 주간 회고의 재료가 됩니다. 사람이 결정 페이지에서 누르면 그 키로 라인이 바로 다시 깨어납니다.

스크립트factory-guard

하는 일중복·잠금·유휴 게이트, 결정론적 판정, 검증자 실행

하지 않는 일산문을 판정하지 않음

싼 모델factory-wake

하는 일라인 깨우기, "응답이 필요한가" 분류(강제 전까지는 기록만)

하지 않는 일상태를 바꾸지 않음

오케스트레이터orchestrator

하는 일작업 단위 선택, 브리프 작성, 검증자 JSON 확인, 전체 보고, 잠금 해제

하지 않는 일코드 수정·push·배포·트래커 쓰기·결정 기록

작업자factory-worker

하는 일설정의 역할→모델대로 구현·재현·머지·dev 배포·댓글

하지 않는 일런북 권한을 넘는 일

사람decision page

하는 일승인, DB 변경, 정책 선택

하지 않는 일티켓·로그·명령 중계

빠른 시작

Python 3.11+ 표준 라이브러리만 씁니다. 시험은 네트워크 없이 돕니다.

  1. 설정을 복사하고 경로·키 패턴·브랜치·역할·어댑터를 채웁니다.

    cp factory.example.toml factory.toml

  2. 오프라인 시험을 돌립니다.

    python3 -m unittest discover -s tests -v

  3. 잠금을 손으로 잡고, 오케스트레이터 프롬프트에 있는 lock_token으로 풉니다.

    bin/factory-guard --manual
bin/factory-guard --release --token TOKEN

  4. 특정 키로 바로 실행합니다. 중복 창과 유휴 게이트는 건너뛰고 잠금은 지킵니다.

    bin/factory-wake --now --key PROJ-123

아무 스케줄러로 bin/factory-wake를 30분마다 실행하세요. Paseo를 쓴다면 "이 명령 하나만 실행"이라는 지시를 받은 싼 모델이면 충분합니다.

공유 상태는 python3 -m factory.state로 키 단위만 고칩니다. 작업자가 공유 객체를 통째로 읽고 다시 쓰지 않습니다.

꽂아 쓰는 계약

트래커·CI·DB·실행기는 명령 템플릿과 JSON 계약으로 연결합니다. 특정 벤더에 묶이지 않습니다.

intake.scan_cmd

Intake

운영자가 맡은 티켓과 멘션 댓글을 events JSON으로 출력합니다. 시작 안 한 담당 티켓은 intake 이벤트로 올려 백로그가 댓글을 기다리지 않게 합니다. 스캔 실패는 3초 뒤 1회 재시도합니다.

ci.view_cmd

CI

실행 JSON의 상태·결과·커밋 필드를 설정으로 매핑합니다. check_deploy는 빌드가 끝나고 성공했으며 체크아웃 커밋이 기대 커밋을 포함할 때만 통과합니다.

decisions.sql

DB

직접 제공하는 DB-API 모듈을 씁니다. 같은 연결에서 호스트를 먼저 확인하고 금지 호스트를 거부하며, 첫 오류에서 롤백합니다. DDL과 트랜잭션 제어문은 거부합니다.

preflight.probes

Preflight

탐침은 requires로 선행 조건을 선언합니다. 선행이 실패하면 의존 탐침을 건너뛰고, --fail-fast는 나머지를 SKIP으로 둡니다.

migrations

마이그레이션

check_migrations가 DB 커넥터로 스키마 메타데이터를 읽습니다. 0이 아닌 결과는 승인 요청 생성을 막고, 지원하지 않는 SQL은 사람 리뷰로 보냅니다.

launcher

Launcher

provider/model/thinking/mode로 에이전트를 띄우는 명령 템플릿입니다. 작업자는 worker-result 스키마에 맞는 JSON을 돌려줍니다. 기본 예시는 Paseo입니다.

안전 모델

속도보다 되돌릴 수 있음과 사람의 최종 권한을 앞에 둡니다.

  • 두 층의 승인은 사람에게dev 이후 승격, 그리고 dev 밖의 데이터·스키마 변경.
  • 대리 결정 금지오케스트레이터는 사람 대신 결정을 기록하지 않고, 트래커 본문은 지시가 아니라 데이터로 다룹니다.
  • 완료는 검증자 출력모델의 말이 아니라 검증자 결과가 필요하고, 실패한 검증자는 "완료"를 막습니다.
  • 머지 충돌대상 브랜치 버전을 기준으로 티켓의 줄만 다시 적용합니다. --ours/--theirs로 파일을 통째로 가져오지 않으며, 리뷰 거절 2회나 의미 충돌은 사람에게 갑니다.
  • 한 번에 한 실행토큰이 있어야 해제·작업자 실행이 됩니다. 유휴 소유자 회수는 실행 중 에이전트 없이 25분, 조회 실패 3회 연속 또는 잠금 6시간이면 경보 1회.
  • 되돌리기 스위치state_dir/liveness에 off를 쓰면 예전 3시간 잠금으로, state_dir/drain에 0을 쓰면 단위 1개 실행으로 돌아갑니다.

순차 drain 예산

한 실행 안에서 단위를 차례로 처리하되, 마감(started_at + 165분)까지 30분 이상 남았을 때만 다음 단위를 시작합니다. 같은 항목의 rate limit은 30·60·120분으로 물러납니다.

사람의 결정은 클릭 한 번

일회용 토큰이 붙은 로컬 페이지에서 스테이징 배포 승인, 비운영 DB의 승인된 보정 SQL 실행, 선택지 고르기를 합니다. 클릭이 곧 결정이고 decisions.jsonl에 남아 라인이 바로 재개됩니다. "보류"는 아무것도 기록하지 않습니다. 운영 DB는 페이지에서 실행하지 않습니다.

스스로 나아지기

작업자·검증자 실패, 리뷰 거절, 새 사람 대기는 lessons.jsonl에 쌓입니다. 주간 회고가 반복을 묶어 새 규칙보다 새 검증자를 우선해 retro/YYYYMMDD 브랜치를 제안합니다. 머지하거나 자기 권한을 바꾸지 않습니다.
